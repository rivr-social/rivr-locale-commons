# File-based docker secrets this module requires.
# Place each as a file at:  ${SECRETS_DIR:-/opt/pm-core/secrets}/<INSTANCE_SLUG>/<name>
# The container sees them at /run/secrets/<name>; bootstrap/start.sh reads them.
#
# PERMISSIONS: the app image runs as non-root (UID 1001 `nextjs`). Compose
# bind-mounts these files with their host permissions, so each MUST be readable
# by that UID. Use `chmod 644` (or 640 + a shared group). A 600/root-only file
# makes the in-container read fail ("Permission denied") and the app crash-loop.
#   chmod 644 ${SECRETS_DIR}/<INSTANCE_SLUG>/*
#
# name       contents
# ---------  ------------------------------------------------------------------
# db_url     Full Postgres connection URL (one line), e.g.
#            postgresql://rivr:<pw>@postgres:5432/rivr_locale
# redis_url  Full Redis connection URL (one line), e.g. redis://:<pw>@redis:6379
#
# MIGRATING FROM THE OVERLAY (flat-secret) MODEL:
# Our live examples/rivr overlays mount a BARE PASSWORD file `rivr_db_password`
# (just the password) plus DATABASE_HOST/PORT/NAME/USER env. This module instead
# wants the WHOLE URL in `db_url` — cleaner for outside operators (provide one
# URL, nothing to assemble). To convert, build the URL from your overlay values:
#   printf 'postgresql://%s:%s@%s:%s/%s' "$DB_USER" "$(cat rivr_db_password)" \
#          "${DB_HOST:-postgres}" "${DB_PORT:-5432}" "$DB_NAME" > db_url
# (URL-encode the password if it contains reserved characters.) bootstrap/start.sh
# still falls back to a mounted `rivr_db_password` if you keep the flat model.
db_url
redis_url
